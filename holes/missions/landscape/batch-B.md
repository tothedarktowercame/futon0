### Judgment Labs — https://www.judgmentlabs.ai/
- **Problem:** Finding out why an agent misbehaves in production, among thousands of multi-step runs, and checking that a fix doesn't break other cases.
- **How:** An Apache-2.0 Python/TypeScript SDK (`judgeval`) sends OpenTelemetry-style spans to a hosted backend that stores traces, runs LLM "judges" over whole trajectories, and lets you query everything in SQL. There is also an MCP server and a Claude Code/Codex plugin.
- **Get:** SDK is Apache-2.0 (GitHub license field, JudgmentLabs/judgeval; ~1.1k stars). Backend is closed and hosted. No public pricing page (/pricing returns 404); pricing unverified. Raised $32M (Lightspeed, May 2026, per their homepage).
- **Build:** Yes for the SDK side (the tracing is OTel-shaped). The backend (trace store, judges, behaviour clustering) isn't public, but its parts are well known: OTel collector + columnar store + LLM-as-judge. A small team could build it in weeks.
- **Use:** Not self-hostable today. The docs say "Self-hosting capabilities ... are coming soon" and to email contact@judgmentlabs.ai. The SDK needs `JUDGMENT_API_KEY` and `JUDGMENT_ORG_ID`, i.e. a cloud account.
- **Verbs:** SDK: `Tracer.init`, `@Tracer.observe(span_type="tool"|"agent")`, `wrap` (client), `Judgeval.sql`, `discover_schema`; classes `Tracer`, `Dataset`, `Judge`. Product: detect, investigate, triage, "search traces", "test fixes against production data", "track behaviors", "extract policy evidence". Research components: Agent Search, Agent Judge, Behavior Discovery, AutoRubrics.

### Braintrust — https://www.braintrust.dev/docs
- **Problem:** Measuring whether a change to a prompt, model or agent made outputs better or worse, both on a fixed test set and on live traffic.
- **How:** SDKs (TypeScript, Python, Java, others) log spans and run `Eval(data, task, scores)` jobs. Results go to a hosted store queried with SQL/BTQL, and a web UI compares experiments side by side. A model gateway/proxy (open source) sits in front of the providers. "Loop" is their in-app agent that reads your traces. The `bt` CLI runs evals (`bt eval`, `--dev`).
- **Get:** Free "Starter" tier: $0, 1 GB processed data/mo, 10k scores/mo, 14-day retention, $10 model credit. Pro $249/mo. Enterprise is custom and the only tier with self-hosting. SDKs are Apache-2.0 (braintrust-sdk-python, braintrust-sdk-javascript). `autoevals` scorer library and `braintrust-proxy` are MIT (GitHub license fields). There is also an Apache-2.0 Terraform module for an AWS "data plane".
- **Build:** The eval loop (dataset × task → scores → diff against baseline) is simple: a few hundred lines plus a store. The UI and query engine are the product, and they're closed. `autoevals` gives you the scorers for free.
- **Use:** Not free to self-host. The self-hosted data plane is Enterprise-only and targets AWS/GCP/k8s. Free cloud account plus Node or Python for the SDK. `autoevals` and the proxy run locally without an account.
- **Verbs:** Workflow from the docs: instrument → trace → evaluate → score → compare experiments → curate datasets → iterate in playground. TS SDK functions: `Eval`, `initExperiment`, `initDataset`, `initLogger`, `initFunction`, `invoke`, `traced`, `wrapTraced`, `startSpan`, `currentSpan`, `currentLogger`, `withParent`, `withCurrent`, `flush`, `loadPrompt`, `getPromptVersions`, `loadParameters`, `logError`, `login`, `permalink`, `reportFailures`, `setMaskingFunction`, `injectTraceContext`, `extractTraceContextFromHeaders`, `defineWorkflowEval`, `agentAssertionScorer`, `configureInstrumentation`, `wrapVitest`, `initNodeTestSuite`. MCP verbs: "query logs, author scorers, configure Topics, run evaluations".

### p2r (Partaker Participation Review) — https://github.com/danoff/p2r
- **Problem:** In a mixed human-and-AI work cycle, each participant needs to record only their own contribution and learning in a fixed, machine-checkable form, without one party writing up the others.
- **How:** A YAML schema (`schema/p2r_schema_v1.yaml`) for one report per partaker per cycle. A Node build script validates the YAML into JSON. CI rejects reports that lack `sovereignty_attestation: true` or that use collective/third-person language in `learning`. A Vite SPA renders the reports and deploys to GitHub Pages. Not a product; it's a convention plus a small repo by Charlie Danoff (May 2026, 0 stars, one sample report). The vocabulary ("peeragogical", `pattern_refs`) suggests it comes from the Peeragogy community.
- **Get:** BSD-3-Clause (GitHub license field and LICENSE file, "Copyright (c) 2026, Charlie Danoff"). Free.
- **Build:** Trivial. The schema is about 100 lines and the whole repo is ~21 KB. The hackathon used it as the proof-of-use report format (`evidence:` / `artifact_produced:`, per the context file).
- **Use:** Yes: Node + npm, static site. Or just write YAML to the schema.
- **Verbs:** `action_type` enum: **decide, create, review, coordinate, reflect**. `pattern_refs`: selected, revised, proposed. `precision_update`: breadth_delta, reliability_delta. Partaker `type`: human, ai. Other fields: `role_this_cycle`, `intent`, `contribution_summary`, `learning`, `attestation_text`, `evidence[]`, `artifact_produced`.

### Reticle — https://www.reticle.sh/
- **Problem:** A coding agent says a web feature works without checking. Screenshots miss silent failures (mock data, a 500 behind a green toast, store out of sync), and re-driving tests with an LLM on every edit costs a lot of tokens.
- **How:** A TypeScript monorepo. A dev-only SDK, injected via Vite/Next/Babel plugins, streams DOM, network, console, store and React-fiber events from the running app to a local daemon (`@reticlehq/server`, port 4400). The daemon exposes MCP tools to the agent. An Apache-2.0 engine adjudicates claims into verdicts with evidence and source `file:line`. Verified flows are saved and replayed deterministically with no model in the loop. `reticle gate` blocks CI when a change touches a flow without a passing re-check. All of this sits on a published spec, the **Open Verification Protocol v1** (`open-verification/SPEC.md`), which has numbered requirements, a conformance suite and test vectors.
- **Get:** Per-package licences (LICENSE file; the GitHub license field says NOASSERTION). Apache-2.0: open-verification, core, engine and all embeddable SDK packages. FSL-1.1-ALv2: server, CLI, init and test; free except for competing use, and each version becomes Apache-2.0 after two years. Source-available Enterprise licence for `server/src/features/ee/`; production use needs a key. Hosted dashboard app.reticle.sh: free tier, no card; paid tiers for teams and run history (exact prices unverified). ~1.2k stars, created June 2026.
- **Build:** Yes. The OVP spec (~630 lines) is detailed enough to implement against, and the engine is Apache-2.0. A realm for a non-browser target (e.g. an Emacs or JVM service) means implementing `identity / channels / determinism / capabilities / describe / dispatch / openWindow / observe / coverage`. Full reimplementation of the browser side would be large (the repo is ~150 MB with assets); the spec plus engine is the portable part.
- **Use:** Yes, locally with no account: `npm i -g @reticlehq/server`, Node, a browser, React/Next (others via `reticle init`). Anonymous telemetry is on by default; turn it off with `reticle telemetry disable` / `DO_NOT_TRACK=1`.
- **Verbs:** **Rich, and conceptually close to FUTON's evidence work.**

### AG-UI protocol — https://docs.ag-ui.com/introduction
- **Problem:** Each agent framework streams its progress (text, tool calls, state changes, pauses for approval) to a user interface in its own format, so every front end has to be rewired for every back end.
- **How:** An open event protocol. The agent backend emits a stream of typed JSON events over HTTP (SSE), WebSockets or a protobuf binary encoding, in response to a `RunAgentInput` (thread, run, messages, tools, state, context). Shared state is sent as snapshots plus RFC 6902 JSON Patch deltas. The canonical definition is `spec/1.0/schema.json`. SDKs are generated or hand-written for TypeScript, Python, Go, Java, Kotlin, Dart, .NET, Ruby and Rust. It positions itself as the agent↔user layer next to MCP (agent↔tools) and A2A (agent↔agent). Made by CopilotKit.
- **Get:** MIT (GitHub license field, ag-ui-protocol/ag-ui; ~16k stars). Free.
- **Build:** Yes, easily. The schema is a single JSON Schema with ~98 definitions. A minimal emitter is an SSE endpoint writing these events; a Clojure or Elisp emitter would be a few hundred lines.
- **Use:** Yes. It's a protocol, so it needs no service. The reference "dojo" app and SDKs need Node or Python.
- **Verbs:** **Full `EventType` enum (spec 1.0, 31 types):** `TEXT_MESSAGE_START`, `TEXT_MESSAGE_CONTENT`, `TEXT_MESSAGE_END`, `TEXT_MESSAGE_CHUNK`, `TOOL_CALL_START`, `TOOL_CALL_ARGS`, `TOOL_CALL_END`, `TOOL_CALL_CHUNK`, `TOOL_CALL_RESULT`, `STATE_SNAPSHOT`, `STATE_DELTA`, `MESSAGES_SNAPSHOT`, `ACTIVITY_SNAPSHOT`, `ACTIVITY_DELTA`, `RAW`, `CUSTOM`, `RUN_STARTED`, `RUN_FINISHED`, `RUN_ERROR`, `STEP_STARTED`, `STEP_FINISHED`, `REASONING_START`, `REASONING_MESSAGE_START`, `REASONING_MESSAGE_CONTENT`, `REASONING_MESSAGE_END`, `REASONING_MESSAGE_CHUNK`, `REASONING_END`, `REASONING_ENCRYPTED_VALUE`, `SUBAGENT_STARTED`, `SUBAGENT_FINISHED`, `SUBAGENT_ERROR`.
  - Removed in 1.0: `THINKING_*` (replaced by `REASONING_*`).
  - Draft: `META` event, with meta types `thumbs_up`, `thumbs_down`, `note`, `tag`, `bookmark`, `copy`, `share`, `rating`.
  - Run outcomes: success, interrupt, cancelled. Subagent outcomes: success, suspended. Resume entry status: `resolved`, `cancelled`.
  - Roles: `developer`, `system`, `assistant`, `user`, `tool`, `activity`, `reasoning`.
  - State patch ops: `add`, `remove`, `replace`, `move`, `copy`, `test`.

### Paritok — https://paritok.com
- **Problem:** Coding agents re-send the same large input every turn (70+ tool schemas, long history, big file reads and tool output), and that drives most of the token bill and fills the context window.
- **How:** A Python HTTP proxy between the agent and Anthropic/OpenAI-compatible APIs (Claude Code points `ANTHROPIC_BASE_URL` at it; Codex uses its `/v1/responses` path). It rewrites each request in three ways. (1) Embedding-based tool filtering (bge-small, CPU): only intent-relevant tool schemas go in full, the rest are stubbed. (2) A 4B compression model compresses tool results and file reads to ~26%, each tagged `[REF:id]`. The model is a LoRA on Qwen3-4B-Instruct-2507 trained on 45K agent trajectories. (3) Old history is summarised. It's "non-destructive" because the agent can call injected tools (`read_original` / `expand_context`, `gateway_search_tools`) to get originals back. Also ships as a LiteLLM Proxy callback and as a direct compression API. Two engineers, no external funding (README).
- **Get:** Apache-2.0 for code (GitHub license field of paritok-official/paritok-4b-v1, ~1.45k stars; PyPI classifiers for `paritok` and `litellm-paritok`) and model weights (HF card `license: apache-2.0`). Hosted GPU: $0.30 per 1M tokens processed. Free through Oct 1 per the README; the context file says $5 free credit, no card. Caveat from the context file: the hosted service sees your prompts **and your upstream API key**.
- **Build:** The proxy and recall-tool idea is a few thousand lines. The trained 4B compressor is the hard part, and it's open.
- **Use:** Yes, self-hostable: `pip install paritok`, then `paritok up`, which pulls the q4 model via Ollama (~2.5 GB; f16 ~8 GB) and serves on :8080. A vLLM path needs a 24 GB GPU. The context file notes the hackathon box (4 cores, 7 GB, no GPU) couldn't run it. CPU Ollama at q4 may run slowly on a bigger box; unverified.
- **Verbs:** CLI: `paritok up`, `paritok proxy` (`--port`, `--config-file`, `--openai-url`), `paritok init`. Agent-facing recall tools: `read_original`, `expand_context`, `gateway_search_tools`. Levers: filter (tools), compress (content), summarize (history), recall/expand.
