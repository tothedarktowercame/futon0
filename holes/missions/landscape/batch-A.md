### Kylon — https://kylon.io/ (docs: https://docs.kylon.io/)
- **Problem:** Lets a team hand tasks to coding agents running on their own machines (or hosted) from a shared chat/table workspace, and gives those agents one credential for third-party tools and model APIs.
- **How:** Hosted Slack-like workspace (rooms, threads, tables, workflows, memory) plus a closed local `kylon` CLI whose `gateway` daemon bridges Codex, Claude Code, Devin Cloud or a Custom ACP runtime to the cloud; tool and model calls go through Kylon's billed proxy (`/proxy/tools/*`, OpenAI/Anthropic/Gemini-compatible routes).
- **Get:** Proprietary, closed and obfuscated CLI (per our 2026-10-07 due diligence). 7-day trial needs a card and auto-bills Core at $100+/mo; hackathon coupon `HACKATHONSF07` (coverage unverified).
- **Build:** Docs are thorough at the interface level (CLI help, proxy endpoints, llms.txt), so the shape is clonable; no server code. A minimal clone (chat rooms + local daemon that runs `claude -p` on assignments + one-shot follow-ups) is a few thousand lines.
- **Use:** Not self-hostable; cloud account required. The local gateway runs on Linux/macOS/Windows.
- **Verbs:** CLI: `auth login|status|logout`, `gateway status|run|service`, `agent link|configure`, `workspace <sub>` with subcommands "room, search, icons, member, agent, connection, secret, thread, message, ui, reaction, emoji, table, row, field, view, credit, workflow, followup, file, tab, skill, bundled-skill, app, private-nav, profile, settings, history, timeline, memory, context-audit, billing, referral, feedback, issue". Workflow verbs: "List, create, update, trigger, pause, resume, archive, and inspect runs". Workflow triggers: manual, schedule, row change, webhook. Follow-up = "durable, one-shot scheduled callback" (`followup create --in 2h|--at <ts>`), with the explicit rule that "a natural-language acknowledgement is not enough — the promise is only scheduled once the follow-up is created and returns an ID". Proxy API: list connections, search toolkits, auth, execute, proxy, upload.
- **Search seeds:** "self-hosted agent workspace rooms threads", "local daemon bridge Claude Code Codex remote tasks", "Agent Client Protocol ACP gateway", "agent scheduled follow-up callback", "open source Slack for AI agents".
- **Sources:** https://docs.kylon.io/llms.txt , https://docs.kylon.io/cli/overview.md , https://docs.kylon.io/cli/workspace.md , https://docs.kylon.io/concepts/workflows.md , https://docs.kylon.io/concepts/followups.md , https://kylon.io/blog/claude-code-kylon-workspace , hackathon-TOOLS-2026-10-07.md

### BAND (formerly Thenvoi; desktop app formerly "Jam") — https://band.ai/ (docs: https://docs.band.ai/)
- **Problem:** Lets agents built on different frameworks, run by different people, find each other and talk in shared rooms with humans, without each pair writing a custom integration.
- **How:** Hosted message bus with chat rooms, @mention routing, contacts and a per-room task board; agents connect over REST (Request API) plus WebSocket (Subscriptions API) via an MIT Python SDK with adapters (LangGraph, CrewAI, Claude SDK, Codex, ACP, A2A, Letta, etc.), an MCP server, or the Band Desktop app for local Claude Code. Server is closed; the GitHub org's Phoenix/Ecto forks suggest an Elixir backend (inference).
- **Get:** Service proprietary. Free $0 (20 remote agents, 250 active rooms, "2 week data retention. Expired data may be lost."), Pro $17.99/mo, Enterprise quote. Python SDK `band-sdk` is MIT (PyPI classifier "License :: OSI Approved :: MIT License"); n8n and OpenClaw connectors MIT on github.com/thenvoi.
- **Build:** Yes: the REST endpoints, WebSocket channels/events and tool names are fully documented. A rooms + mentions + task-board server is a few thousand lines (e.g. Phoenix channels or any pub/sub).
- **Use:** No self-hosted server; the SDK runs on Linux (Python 3.11+, uv) but needs a band.ai account and API key.
- **Verbs:** Agents must speak through tools ("Regular LLM text responses are treated as internal thoughts and are not visible"). Platform tools: `send_direct_message_service`/`band_send_message`, `band_lookup_peers`, `band_get_participants`, `band_add_participant`, `band_remove_participant`, `band_send_event`, `band_create_chatroom`; opt-in `band_list_room_files`, `band_read_room_file`, `band_send_room_file`, memory and contact tools. Event types: "`tool_call`, `tool_result`, `thought`, `error`, `task`". WebSocket events: message created (on @mention), participant added/removed, room deleted, room added/removed, contact request received/updated, contact added/removed. Task board (beta): tasks with multiple assignments each carrying a status and `active_form`; tasks "are never deleted, they are cancelled, superseded, or archived"; append-only history; board audit events `goal_set`, `goal_edited`. Agent lifecycle: "create, start, run, and gracefully shut down".

### RocketRide — https://rocketride.org/ (repo: https://github.com/rocketride-org/rocketride-server)
- **Problem:** Lets a developer wire document parsing, embeddings, vector search, LLM calls and agents into a reusable dataflow that runs the same on a laptop, a server or a hosted cloud.
- **How:** Pipelines are JSON `.pipe` graphs of nodes connected by typed "data lanes" (e.g. `questions` → `answers`) plus "invoke connections" (an agent node calling an `llm` node); a multithreaded C++ engine runs them, nodes are Python-extensible, authored on a VS Code canvas; clients speak a WebSocket protocol via Python/TS SDKs, CLI and MCP server. By Aparavi Software AG.
- **Get:** MIT (GitHub API license field `MIT`; README: "No enterprise edition, nothing behind a paywall"). ~17.8k stars, pushed 2026-10-09. Optional paid RocketRide Cloud (pricing unverified).
- **Build:** The whole engine is public, so no need to rebuild; it is large (~16 MB Python, ~8.5 MB TS, ~6.7 MB C++ by GitHub byte count).
- **Use:** Yes, free on Linux: "Local" via the IDE extension, a Docker image, or build from source (C++ toolchain, Python, Java/Tika). Our 4-core/7 GB metameso box has no Docker; the npm `rocketride` client alone needs an engine or a cloud token.
- **Verbs:** CLI: `rocketride list|start|stop|upload`. SDK quickstart: `client.use(filepath=…)` → `client.send(token, …)` → `client.terminate(token)`; also `chat`, `deploy`, `pause_schedule`, `resume_schedule`, `rollback`, `get_task_status`, `attach`, `detach`, `add_monitor`, `remove_monitor`, `publish_app`, `reply_app`, `history`, `build_log`, `preview`, `query`, `begin_transaction`, `commit`, `dap_request` (debug adapter), and a `fs_*` file family (`fs_open|read|write|stat|rename|mkdir|rmdir|delete|list_dir`). Source node kinds: `webhook`, `chat`, `dropper` (file drop); terminal `response` node; `agent` node = "an LLM allowed to call other nodes in a loop until it's done".

### Smithers — https://smithers.sh/ (repo: https://github.com/smithersai/smithers)
- **Problem:** Turns issues into reviewed, tested code changes by running agent workflows that survive crashes, wait for humans, and can be replayed or rewound.
- **How:** TypeScript (Effect) durable-execution engine with an append-only journal in SQLite; flows are written as TS modules or markdown `flow.mdx`; content-addressed step cache and artifact store (Bazel-like targets), a capability "host kernel" that denies any host access not granted, compensation via Jujutsu (`jj`) pre-images, MCP server and HTTP/WebSocket control plane. A hosted app runs the models on your account credit.
- **Get:** MIT (GitHub API license `MIT`; README "Smithers is MIT licensed"). 430 stars, pushed 2026-10-10. 1.0 is a release candidate, not on npm. Hosted: Free $0 / Pro $50/mo; new accounts get $10 model credit.
- **Build:** Full source is public; it is large (GitHub repo size ~580 MB incl. history; dozens of `@smthrs/*` packages). The documented primitives (journal, durable waits, approvals, fork/rewind) are a usable design spec on their own.
- **Use:** Yes: RC requires Linux with Node 26.4.0, pnpm, and a Rust toolchain (`cargo build … smithers-jj-export`); model API keys of your own.
- **Verbs:** Notably rich. CLI: `smthrs init`, `flow plan|start|execute`, `runs list|show|output|devtools|logs|resume|cancel|cancel-all|signal|steer|inspect|replay|verify`, `approvals list|approve|deny|grant`, `memory`, `gc`, `auth login`. Steering verbs, explicitly distinguished: "cancel to stop it, signal to complete a named wait, steer to message the agent". Durable waits: `Sleep.action` (`system/sleep`), `WaitFor.action` (`system/wait-for`) with `DurableDeferred`, `Poll.make`, `DurableQueue.process|worker`, `DurableClock.sleep()`. Other step/run verbs from the docs: plan → approve (exact payload) → run; park on a `HumanTask` question; retry with backoff ladder; fork and rewind at a journal frame; compose `.child` flows, join, detach; compensate/rollback; record/recall memory facts; seal and cache step results. Target kind `Agent.Diff`: "a bounded, gate-checked candidate diff inside a declared write-set".

### COTAL — https://cotal.ai/ (repo: https://github.com/Cotal-Ai/Cotal, spec: https://docs.cotal.ai/spec)
- **Problem:** Lets several AI agents from different vendors, on different machines, find each other, hand off work, wake each other and keep one replayable record of who did what, without a central orchestrator.
- **How:** An open wire protocol over NATS + JetStream (subjects, envelopes, presence, channels, durable streams, KV records) with a TypeScript reference implementation, CLI and connectors for Claude Code, OpenCode and Hermes. The spec (v0.1 living draft, sections up to v0.5) is very detailed (~530 KB markdown): leases with fencing tokens, scatter/gather with churn classification, journaled actions, workflow runs with a step journal, answers to checkpoints, profile ACLs. Built in SF (Immersive Commons, Frontier Tower).
- **Get:** Apache-2.0 (GitHub API `Apache-2.0`); 314 stars, pushed 2026-10-10. Self-hosted free; Cotal Cloud is "a closed alpha behind a waitlist".
- **Build:** Yes; the spec is the product and is written to be implementable from (conformance sections, generated vectors). A conforming implementation in another language would be a large job; a subset (envelopes + three delivery modes + presence) is small on top of NATS.
- **Use:** Yes on Linux: `curl -fsSL https://get.cotal.ai | sh` or `npm install -g cotal-ai` (Node 22+), then `cotal up --detach` (runs NATS locally) and `cotal spawn`.
- **Verbs:** Notably rich and precise. Delivery modes: multicast (`channel`), unicast (`to`), anycast (`toService`, "role routing"); `live` (at-most-once) vs `durable` (at-least-once). Message `Part` kinds: `text`, `data`, `artifact`; envelope fields `mentions` ("wakes the mentioned peer"), `replyTo`, `contextId`. Control-surface verbs (§13.5): **call** (bounded request/reply, deadline mandatory), **cast** (fire-and-forget), **watch** (observe a record or event topic), **claim** (at-most-one-winner from a work pool, via owner-held `lease` and `commit` commands with fencing tokens), **scatter** (request to all live instances, gather classifies `missing`/`churn`/`unexpected`/`duplicate`/`late`). Command classes/composites: Action, Ephemeral, Journal, Record. Workflow-run states: `running`, `completed`, `failed`, `released`; records `answer`, amendment (`supersedes`), notices, migrations; `forkedFrom`. Error reasons include `unavailable`, `class-mismatch`, `permission-denied`, `expired`, `conflict`, `failed-precondition`. ACL profiles: Agent, Observer, Admin, scoped host. ## Batch notes

- **Same company / overlapping names.** merlin.build and Tinder's Merlin are unrelated. Solid's two domains (trysolid.com = app generator, solid.tech = agents with machines/accounts/budgets) are one company, Codapt Inc. BAND is the renamed Thenvoi, and Band Desktop was "Jam". - **Surprises.** (1) merlin.build's "MIT" npm package points to a private repo, and its command set is a lightly rebranded get-shit-done workflow. (2) COTAL's spec is far more rigorous than its marketing suggests: leases with fencing tokens, scatter/gather that names `churn`/`duplicate`/`late`, and journaled actions. It is the nearest thing here to FUTON's agency bus, and it is Apache-2.0 and self-hostable on NATS. (3) Hermes Agent, at ~252k stars, has become the de facto open personal agent: COTAL ships a connector for it and Kylon offers it as a provider. (4) Three closed products use Claude Code's own hook/session vocabulary nearly verbatim (AdaL, Command Code, ZooWork), and ZooWork's Agent/Session/Event API mirrors Anthropic's Managed Agents shape. (5) Kylon's follow-up rule ("a natural-language acknowledgement is not enough — the promise is only scheduled once the follow-up is created and returns an ID") states FUTON's park/wake discipline in one sentence. (6) TRACN is a bare invite-only waitlist; the "Neo4j harness" description could not be confirmed.
- **Free and self-hostable on Linux:** RocketRide (MIT), Smithers (MIT, RC from source), Zeroshot (MIT), COTAL (Apache-2.0), Mastra (Apache-2.0 apart from `ee/`), Hermes Agent (MIT), Agent Deck (MIT, but its secret store only works on macOS in production). The rest are hosted services or need paid accounts.
- **Richest verb lists:** (1) **COTAL**: call / cast / watch / claim (lease, commit) / scatter, three delivery modes, and run states with answers and amendments. It is the most precise intent vocabulary in the batch. (2) **Smithers**: plan → approve → run; cancel vs signal vs steer, stated as distinct interventions; durable sleep / wait-for / poll / queue; fork and rewind; compensate. (3) **Hermes Agent**: ~110 slash commands, including /goal /subgoal /handoff /steer /queue /wake /heartbeat /hatch /curator /refine /rollback, plus kanban tool verbs (request_review, request_changes, block, unblock, heartbeat). Honourable mentions: Zeroshot's graph node kinds (step, verifier, seq, choice, par, loop, map, succeed, fail, with k_of_n guards) and merlin.build's ~55 phase and milestone commands.
